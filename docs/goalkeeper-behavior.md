# Phase 6 自动守门设计

## 目标与边界

Phase 6 把已通过实车的“看球并发送三轴速度”扩展为完整守门行为：估计车和球在
球场中的状态，判断球是否威胁己方球门，移动到预测拦截点，并在威胁解除后回到
守门区域。

当前代码和模型包含 `football`、`goal` 两类，但当前测试场地没有球门框。球门检测、
己方/对方区分和球门位姿解算均未实场验证。Phase 6 不把现有球框比例或 MPU6050
漂移 yaw 当作绝对距离、位置或航向。

## 坐标与模块

正式控制区分图像、相机、车体和球场四套坐标。球场原点暂定为己方球门中心，X 沿
球门线，Y 从己方球门指向场内。现有 C5 三轴符号只在车体适配层处理，上层行为不
直接依赖相机安装方向和电机符号。

```text
球/球门检测
  → 时间同步与目标跟踪
  → 相机/车体/球场坐标变换
  → 车位、球位与球速估计
  → 威胁判断与守门状态机
  → 目标位置/航向控制
  → 安全监督
  → MotionLink
```

感知层至少输出检测框、类别、置信度、原始帧时间和数据年龄。球优先使用落地点或
已知球尺寸投影到地面；球门需要完整框，后续最好提供门柱/角点。所有状态估计都带
时间戳和置信度。

## 行为状态机

| 状态 | 行为 |
|---|---|
| `DISABLED` | 未 ARM，三轴为零 |
| `LOCALIZING` | 确认己方球门、车位和球场坐标，不主动追球 |
| `HOLD` | 保持守门线和默认位置，低增益沿球门线跟随 |
| `INTERCEPT` | 球朝己方球门运动时前往预测拦截点 |
| `BLOCK` | 到达拦截区域后短时保持 |
| `RECOVER` | 威胁解除后返回守门线/球门中心附近 |
| `TARGET_LOST` | 零速等待重捕获，不立即结束运行任务 |
| `FAULT` | 位姿、数据或链路失效，STOP 并解除 ARM |

短时丢球只令速度归零并保留运行会话；持续丢球或定位失效才解除 ARM。具体时限由
录像回放和实车数据确定，STM32 的 200 ms HOST 看门狗不变。

## 轨迹与拦截

球场状态至少包含 `(x, y, vx, vy, timestamp, confidence)`。当球朝己方球门运动时，
预测其到达守门线的时间与横向位置：

```text
t_cross = (guard_depth - ball_y) / ball_vy
x_cross = ball_x + ball_vx * t_cross
```

只有预测时间有效、落点进入球门范围且状态可信时才进入 `INTERCEPT`。目标横坐标
限制在守门范围，并按底盘速度和剩余时间裁剪到可达位置。无直接威胁时只低速影子
跟随，不离开守门区追球。

正式守门优先保持车头相对球场的参考航向：`vx` 沿球门线拦截，`vy` 返回守门深度，
`wz` 修正航向。Phase 5D 的“转向使球居中”已完成软件实现，只作为视野保护或降级
策略，不能替代球场航向控制。

## 定位输入

实施前需补齐：

- 相机内参及相对车体的安装位置、朝向和高度；
- 球、场地和球门尺寸；
- 己方/对方球门区分；
- 能持续修正车位和航向的视觉锚点；
- 检测框到原始图像坐标的可靠还原。

MPU6050 只提供短时转动信息，不能独立提供绝对 yaw。无轮编码器时也不能长期依赖
速度指令积分。若规则允许，己方球门上的 AprilTag/Aruco 是最直接的位姿与身份锚点；
否则需要球门门柱/关键点、场地线或其他视觉特征。

## 实施顺序

1. 数据接口与采集：统一 `PerceptionFrame`，增加球门跟踪、CSV 和同步标注视频；
2. 离线回放：同一段录像可重复运行定位、跟踪和行为算法；
3. 守门线 MVP：已知起点和朝向，只做有界横向防守；
4. 标定与定位：输出车、球的球场坐标和置信度；
5. 轨迹预测：实现 `HOLD → INTERCEPT → BLOCK → RECOVER`；
6. 分级实测：静止球、慢速滚动球、横向/斜向来球、丢球和定位失效。

## 新任务交接边界

Phase 6 建议在新的 Codex 任务实施。首个纵向目标为感知数据契约、`GoalTracker`、
同步记录、离线回放和状态机骨架；默认只 dry-run，不自动 ARM、烧录或动车。球场
定位和实车拦截在输入与验收条件齐全后分别推进。
跨用户恢复基线、外部资产和首轮边界见 [handoff-phase6.md](handoff-phase6.md)。
