# 侧置相机球控

## 相机坐标

用户实测相机装在车右侧，控制轴按镜头运动解释：

```text
球在画面左侧 → vx > 0；球在右侧 → vx < 0
球框偏小（远）→ vy > 0；球框偏大（近）→ vy < 0
球在画面左侧 → wz < 0；球在右侧 → wz > 0
```

`vx` 控制镜头左右，`vy` 控制镜头前后，`wz` 控制朝向。此前把 `vx` 设计成
只正不负的前进量，导致镜头持续向左，已废弃。

## 参数

| 轴 | 输入 | 死区 | `Kp` | 最小 | 最大 | 单周期变化 | 符号 |
|---|---|---:|---:|---:|---:|---:|---:|
| `vx` | 水平归一化误差 | 0.10 | 1000 | 250 | 800 | 120 | -1 |
| `vy` | `0.35 - 框高比例` | 0.05 | 4000 | 200 | 600 | 100 | +1 |
| `wz` | 水平归一化误差 | 0.10 | 220 | 40 | 180 | 20 | +1 |

三个轴换向均先过零。三轴绝对值之和超过 1000 时在上位机同比缩放，再发送给 STM32。
框高比例 0.30–0.40 视为暂定距离死区；该比例受模型、视角和遮挡影响，不是真实距离。

## 安全与数据

- 20 Hz，连续三周期有效目标后才 ARM；
- 默认 dry-run，只有 `--execute` 才发送 `vx,vy,wz`；
- 丢球持续刷新零 TWIST，重新连续确认后恢复；
- 链路错误、Ctrl+C、到时和异常退出均尝试全局 STOP；
- STM32 200 ms HOST 看门狗保持不变；
- 每次 Phase 5C 自动写 `logs/ball-follow-时间.csv`，也可用 `--control-log` 指定路径；
- CSV 逐周期记录框、置信度、两类误差、目标/发送三轴、ARM/暂停和 IMU 姿态。

## 使用

```bash
# 无运动检查
python3 main.py --headless --mode ball-follow-test

# 明确授权后才执行
python3 main.py --headless --mode ball-follow-test --execute
```

## 验收

1. 左/右球产生正/负 `vx`，远/近球产生正/负 `vy`，中央目标距离三轴为零；
2. dry-run 左右移动球并改变远近，核对控制台与 CSV；
3. 实物逐项确认镜头左右、前后和转向方向；
4. 丢球、低置信度和到时均停车；
5. 最终 QUERY 为 `HOST/DISARMED/STOPPED/errors=0`。

## 迭代记录

- 旧 `vy+wz` 方案的相机坐标解释错误，已废弃；
- 只正不负的 `vx+wz` 方案使镜头持续向左，已废弃；
- 当前三轴相机控制通过本机/板端 57 项测试；5 秒 dry-run 生成 60 行 CSV；
- 30 秒实车行为通过，用户确认镜头随球正确移动；最终 QUERY 无错误；
- 实车 CSV 514 周期：`vx` 负/零/正为 108/266/138，`vy` 为 131/288/93，
  `wz` 为 138/266/108；最大周期间隔 116.7 ms；
- 21 个无目标和 2 个低置信度周期全部发送零速。

## Phase 5D：窄视角保护

状态：本机/板端 65 项测试和 dry-run 通过，实车待验。

Phase 5C 已同时生成平移和转向，但三轴共用误差并同比分配预算，不会主动保证球留在
较窄视野内。Phase 5D 新增独立 `ball-fov-test`，不改变 5C 默认行为，也不依赖球门
或球场定位：

- 对水平误差设置中央、跟踪和边缘三区，并使用进出阈值滞回；
- 中央区保留当前三轴控制，边缘区优先分配 `wz`，降低 `vx/vy`；
- 用滤波后的水平误差速度预测 150 ms 后的画面位置，提前进入视野保护；
- 只允许最近一次高置信度观测驱动最多 150 ms 的转向预测，超龄后立即三轴归零；
- 丢球不结束会话，归零等待重捕获；禁止盲目平移和无限扫转；
- CSV 增加滤波误差、误差速度、预测误差、区域、目标年龄和丢帧数。

默认参数：

| 项目 | 值 |
|---|---:|
| 误差/速度滤波系数 | 0.55 / 0.35 |
| 预测时间 / 丢帧预测保持 | 0.15 s / 0.15 s |
| 进入/退出边缘区 | 0.55 / 0.30 |
| 边缘区平移比例 | 0.25 |
| `wz` | 60–260，`Kp=320` |

```bash
# 无运动检查
python3 main.py --headless --mode ball-fov-test

# 实车仍需再次明确授权
python3 main.py --headless --mode ball-fov-test --execute
```

边缘区先保留 `wz`，再把剩余协议预算分给平移。短时预测不会触发首次 ARM，且只向
已 ARM 会话发送 `vx=vy=0` 的有限转向；重新看到球后仍需连续三周期确认才恢复三轴。
本机与板端完整 RK 测试均为 65 项通过，包含滞回、提前入区、预算优先、重复周期
稳定、预测超时和会话安全。板端 5 秒 dry-run 约 56 FPS，写入 58 行 CSV；画面无球，
全程未 ARM，最终 QUERY 为 `HOST/DISARMED/STOPPED/errors=0`。

默认阈值仍需通过带球 CSV/录像确认，再做限时实车验收。
该模式解决视野保持，不承担球场定位或正式守门决策；后续见
[goalkeeper-behavior.md](goalkeeper-behavior.md)。
